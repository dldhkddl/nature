# 스마트스토어 상품별 카테고리·필수값 검사 설계

**작성일:** 2026-08-05  
**상태:** 승인됨  
**대상:** 개인용 `smartstore-ai`

## 1. 목표

스마트스토어 직접 등록 전에 상품별 네이버 말단 카테고리와 공통 필수값을 검사해, 고정 카테고리 사용과 누락·잘못된 값으로 인한 오등록을 막는다. 동시에 현재의 낡은 테스트와 린트 오류를 정리해 이후 기능 개발의 검증 기반을 정상화한다.

## 2. 범위

### 포함

- 상품 편집 화면에서 네이버 카테고리 검색 및 선택
- 상품마다 네이버 말단 카테고리 ID와 표시 경로 저장
- 공통 필수값 검사: 상품명, 카테고리, 판매가, 재고, 대표 이미지, 원산지
- 판매가와 재고의 양의 정수 검사
- 화면의 등록 준비 상태 및 누락 항목 표시
- 필수값 누락 시 네이버 등록 버튼 차단
- 네이버 등록 API의 동일한 서버 측 재검사
- 환경변수 고정 카테고리 대신 상품별 카테고리 사용
- 검증 규칙 단위 테스트
- 제거된 초기 Sites 화면을 검사하는 낡은 테스트 교체
- 기존 린트 오류 4개 수정
- 최종 빌드·린트·테스트 검증

### 제외

- 로그인, 권한, 다중 사용자 기능
- 네이버 카테고리별 상품정보제공고시·속성 전체 검사
- 쿠팡·카페24 직접 등록 검증 확대
- 일괄 등록과 등록 이력
- 상품의 D1 서버 저장 전환
- 배포 및 호스팅 변경

## 3. 접근 방식

화면과 API에 검증 로직을 중복 작성하지 않는다. 부작용이 없는 공유 검증 모듈을 만들고, 클라이언트의 등록 준비 표시와 서버 API의 최종 차단이 같은 결과를 사용하게 한다. 화면 검사는 빠른 피드백을 제공하고, 서버 검사는 우회 요청을 막는 최종 안전장치다.

## 4. 데이터 모델

상품의 기존 공통 데이터 `CanonicalRow`에 다음 값을 저장한다.

- `category`: 네이버 말단 카테고리 ID
- `categoryName`: 사용자가 확인할 수 있는 전체 카테고리 경로 또는 카테고리명

기존 상품에 값이 없으면 자동 추측하거나 환경변수로 대체하지 않는다. 사용자가 네이버 카테고리 검색 결과에서 직접 선택해야 등록 가능 상태가 된다.

## 5. 검증 규칙

네이버 직접 등록에 필요한 공통 규칙은 다음과 같다.

| 필드 | 규칙 |
|---|---|
| 상품명 | 공백 제거 후 1자 이상 |
| 카테고리 | 숫자로만 구성된 말단 카테고리 ID |
| 판매가 | 0보다 큰 정수 |
| 재고 | 0보다 큰 정수 |
| 대표 이미지 | 이미지가 최소 1장 존재 |
| 원산지 | 공백 제거 후 1자 이상 |

검증 결과는 필드별 오류 목록으로 반환한다. 첫 오류만 보여주지 않고 사용자가 한 번에 모두 수정할 수 있도록 전체 목록을 표시한다.

## 6. 화면 흐름

1. 사용자가 상품 편집 화면에서 카테고리 검색어를 입력한다.
2. 기존 네이버 카테고리 검색 API가 말단 카테고리 목록을 반환한다.
3. 사용자가 항목을 선택하면 카테고리 ID와 경로가 현재 상품에 저장된다.
4. 등록 영역에 `등록 준비 완료` 또는 누락 항목 목록을 표시한다.
5. 오류가 있으면 네이버 등록 버튼을 비활성화한다.
6. 오류가 없을 때만 등록 요청을 보낸다.
7. API가 같은 검증을 다시 수행하고 실패 시 구조화된 오류 응답을 반환한다.

## 7. API 변경

`POST /api/naver/register`는 폼 데이터에서 상품별 `category`를 받는다. `NAVER_LEAF_CATEGORY_ID`는 등록 카테고리로 사용하지 않는다. API는 외부 토큰 발급과 이미지 업로드 전에 필수값을 먼저 검사해, 잘못된 요청에 비용과 네트워크 호출이 발생하지 않게 한다.

검증 실패 응답은 HTTP 400과 다음 형태를 사용한다.

```json
{
  "error": "등록 필수값을 확인해 주세요.",
  "issues": [
    { "field": "category", "message": "네이버 카테고리를 선택해 주세요." }
  ]
}
```

## 8. 기반 안정화

- 삭제된 `app/_sites-preview`를 가정하는 테스트는 제거한다.
- 새 테스트는 공유 검증 함수의 정상값, 누락값, 숫자 경계값, 잘못된 카테고리를 검증한다.
- React effect 안의 동기 상태 변경으로 발생하는 린트 오류는 초기화 책임을 명확히 분리해 해결한다.
- 사용자 변경과 무관한 파일은 수정하지 않는다.

## 9. 성공 기준

- 각 상품이 서로 다른 네이버 카테고리를 저장할 수 있다.
- 카테고리를 선택하지 않은 상품은 네이버에 등록할 수 없다.
- 필수값 누락과 잘못된 판매가·재고를 화면에서 한 번에 확인할 수 있다.
- 직접 API를 호출해도 동일한 누락 요청이 HTTP 400으로 거부된다.
- 네이버 등록 요청에는 상품별 카테고리 ID가 전달된다.
- `npm run build`, `npm run lint`, `npm test`가 모두 성공한다.
